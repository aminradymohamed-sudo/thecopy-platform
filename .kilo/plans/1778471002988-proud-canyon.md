*ملاحظة: الفحص الأولي (تم تنفيذه) أظهر أنه لا يوجد استخدام صريح لـ `<script>` أو `dangerouslySetInnerHTML` كحقن نصوص مباشر يهدد عمل الـ CSP، وجميع استخدامات `<style>` المدمجة هي مكونات معزولة أو داخل دوال معالجة حماية (`sanitize-html.ts`).*

## 🔐 2. توليد Nonce آمن (Cryptographically Secure)
تلبيةً لمعايير OWASP (128-bit entropy)، يتم استبدال `randomUUID` المعيب بالمقاربة التالية:

- **في `apps/web` (Edge Runtime):**
  نستخدم Web Crypto API المتوافق مع Edge.
  *ملاحظة: `Buffer` متاح في Next.js Edge Runtime كـ polyfill. لصرامة معيارية أكبر (Web Standard خالص)، يمكن استخدام `btoa()` مع تحويل يدوي لأحرف `base64url`.*
  ```typescript
  const array = new Uint8Array(16);
  crypto.getRandomValues(array);
  // باستخدام btoa القياسي
  const base64 = btoa(String.fromCharCode(...array));
  const nonce = base64.replace(/\+/g, '-').replace(/\//g, '_').replace(/=+$/, '');
  ```
- **في `apps/backend` (Node.js):**
  نستخدم مكتبة `node:crypto`:
  ```typescript
  import { randomBytes } from "node:crypto";
  const nonce = randomBytes(16).toString("base64url");
  ```
*ملاحظة: استخدام `base64url` يمنع ظهور أحرف `+`، `/`، `=` التي تكسر معالجة الترويسات.*

## 🌐 3. التنفيذ في الواجهة (apps/web)

### أ) الميدلوير (`apps/web/src/proxy.ts`)
1. توليد الـ Nonce بالطريقة الآمنة المذكورة أعلاه في الدالة الرئيسية.
2. إضافة خاصية `nonce` واختيارياً رابط `sentryOrigin` لتوجيه الـ violations ضمن `ContentSecurityPolicyOptions`.
3. تعديل `script-src`:
   - إزالة `'unsafe-inline'`.
   - إضافة `'nonce-${nonce}'`.
   - إضافة `'strict-dynamic'` (للسماح للسكربتات الموثوقة باستدعاء سكربتات أخرى، مهم لـ Sentry وGoogle APIs).
   *تحذير: `strict-dynamic` يُلغي مفعول `'self'` و الـ host whitelists لأي سكربت. أي سكربت لا يُحمَّل عبر nonce سيُحجب حتى لو كان على نفس النطاق.*
4. تعديل `style-src`:
   - إزالة `'unsafe-inline'`.
   - إضافة `'nonce-${nonce}'`.
5. إضافة توجيه التقرير `report-uri`:
   - إضافة `report-uri https://o4511284205453312.ingest.us.sentry.io/api/4511284205453312/security/?sentry_key=YOUR_KEY` (أو استخدام الـ Sentry Endpoint الكامل الصحيح للمشروع) لالتقاط أي خروقات CSP في الإنتاج. 
   *(ملاحظة: `report-to` هو التوجيه العصري كبديل لـ `report-uri` المتقادم في CSP3، ولكن `report-uri` لا يزال مدعوماً على نطاق واسع في المتصفحات).*
6. حقن الترويسة `x-nonce` و `Content-Security-Policy` في طلبات Next.js وفي الـ Response.

### ب) الـ Layout (`apps/web/src/app/layout.tsx`)
قراءة الـ `x-nonce` وتمريرها لمكونات الطرف الثالث:
```tsx
import { headers } from "next/headers";
// ... داخل المكون
const nonce = (await headers()).get("x-nonce") ?? undefined;

// تمرير الـ nonce للـ Analytics والـ SpeedInsights
<SpeedInsights nonce={nonce} />
<Analytics nonce={nonce} />
```

### ج) الاختبارات (`apps/web/src/middleware.test.ts`)
تحديث الاختبارات لفحص إزالة الثغرة باختبار معزول:
```typescript
import { buildContentSecurityPolicy } from "./proxy";

it("builds correct CSP without unsafe-inline and includes nonce", () => {
  const mockNonce = "mocked-nonce-123456";
  const header = buildContentSecurityPolicy({
    isDevelopment: false,
    nonce: mockNonce,
    sentryOrigin: "https://o4511284205453312.ingest.us.sentry.io"
  });

  expect(header).not.toContain("'unsafe-inline'");
  expect(header).toContain(`'nonce-${mockNonce}'`);
  expect(header).toContain("'strict-dynamic'");
  expect(header).toContain("report-uri https://o4511284205453312.ingest.us.sentry.io");
});
```

## ⚙️ 4. التنفيذ في الخلفية (apps/backend)

### أ) الميدلوير (`apps/backend/src/middleware/csp.middleware.ts`)
- إزالة الكلمة المفتاحية `'unsafe-inline'` من مصفوفة `"style-src"`.
- تحديث دالة `generateNonce` لتعود بـ `randomBytes(16).toString("base64url")` مباشرة.
- إضافة `report-uri` (أو `report-to`) إلى قاموس الـ `CSP_DIRECTIVES` وتوجيهه إلى المسار الكامل لـ Sentry Endpoint.

### ب) الاختبارات (`apps/backend/src/__tests__/middleware/csp.middleware.test.ts`)
- إضافة تأكيد برمجي صريح (Assertion) بأن الترويسة لا تحوي `'unsafe-inline'`:
  ```typescript
  it("يجب ألا يحتوي CSP على unsafe-inline في الإنتاج", () => {
    // ... setup mock req/res
    cspMiddleware(req, res, nextFn);
    const cspHeader = res._headers["content-security-policy"];
    expect(cspHeader).not.toContain("unsafe-inline");
    expect(cspHeader).toContain("report-uri");
  });
  ```

## 🧩 5. التعامل مع الحالات الحرجة (Edge Cases)

- **Hydration & Next.js 16 Streaming Styles:** يتم حلها تلقائياً بمجرد تمرير ترويسة `Content-Security-Policy` في الـ Request؛ يقرأها Next.js ويُلحق الـ Nonce بجميع إنتاجاته (بما فيها `styled-jsx`).
- **فحص next/script صراحةً:** يجب التأكد من تمرير `nonce={nonce}` لأي استخدام مباشر لـ `<Script>` من مكتبة `next/script` في الكود (وهذا ينطبق على نصوص بدء التشغيل في الـ Layouts).
- **dangerouslySetInnerHTML:** سيتم حظر أي `<script>` مُضمن بداخلها. يتم كشفها عبر خطوة الاستكشاف الأولى ومعالجتها.
- **Service Workers:** سياسة `worker-src 'self' blob:` كافية ولا تتطلب Nonce.

1. **تشغيل الاختبارات آلياً:** 
   - `pnpm test` (للتأكد أن الاختبارات المحدثة تنجح، وأنها تفشل لو تمت إعادة `unsafe-inline`).
2. **تشغيل أوامر البناء (Build) منفصلة:** للتأكد من عدم الفشل في البناء:
   ```bash

   ```

   - إضافة سيناريو يفحص ظهور الـ nonce بشكل صحيح في عناصر الـ DOM الحقيقية.
4. **الفحص اليدوي للصفحات الحرجة:**
   - الدخول إلى مسارات محددة: `/editor` و `/breakdown` و `/actorai-arabic`.

   - فتح Elements في المتصفح، والبحث عن `<script>` و `<style>` المضمنة (inline) والتأكد صراحةً أنها جميعاً تحمل الخاصية `nonce="..."` وأنها لا تُحجب.

   - عمل Refresh للصفحة مرتين متتاليتين، والتأكد من Network tab أن قيمة `x-nonce` متغيرة وغير مكررة.

## ⏪ 7. خطة التراجع السريع (Rollback Plan)

- **نوع التراجع (Selective):** يمكن التراجع عن الواجهة أو الخلفية بشكل منفصل حسب مصدر العطل.
- **التنفيذ الفعلي:** عبر أوامر واضحة مثل `git revert <commit-sha>` لضمان نظافة السجل.
- **الهدف الزمني (MTTR):** هدف التراجع الكامل يجب أن يكون **أقل من 10 دقائق من الكشف**.
- **معيار التراجع (Threshold):**
  - في حال تعطل صفحة أساسية بالكامل (مثلاً شاشة بيضاء في `/editor`).
  - أو في حال أرسل المتصفح أخطاء حجب عبر `report-uri` تتجاوز حدوثها 1% من المستخدمين أو أكثر من 15 دقيقة بعد النشر في Sentry.
- **بديل التراجع (Report-Only):**
  - يمكن تغيير `Content-Security-Policy` إلى `Content-Security-Policy-Report-Only`، لتعمل سياسة الإبلاغ فقط دون حظر التنفيذ لتحديد المشاكل بشكل آمن.

## 🔍 8. التحقق ما بعد التنفيذ (Post-Execution Verification)

1. **التحقق الآلي الإلزامي (DAST):** إعادة تشغيل فحص ZAP-Baseline الإلزامي والتأكد أن المشكلتين `10055-5` و `10055-6` (CWE-693) لم تعد تظهر في التقرير (Count: 0).
2. **التحقق من الخادم وحقن الـ Nonce:** فحص الـ HTML المسترد صراحةً للتأكد من أن Next.js التقط الـ nonce من الـ headers وأضافه إلى وسم الـ `<html>`.
3. **مراقبة الإنتاج و `report-uri`:** مراقبة تقارير الـ CSP Violations الواردة إلى Sentry (عبر الـ endpoint الكامل الذي قمنا بإعداده) والتأكد من عدم وجود خروقات عشوائية لسكربتات شرعية تابعة للموقع بعد التطبيق.
